# KDE development

The KDE adapter uses Kirigami with CXX-Qt 0.10 and a QML AppController object. Home and Workspace are separate Kirigami.ApplicationWindows with ScrollablePage/Page content. The workspace uses a native `Kirigami.PageRow` with a non-modal `OverlayDrawer` in `leftSidebar`. Its `interactiveResizeEnabled` property enables Kirigami's own mouse resize handle, including the header edge. A standard ToolBar in the drawer uses the PageRow toolbar height; Kirigami draws the segmented header separator and keeps it aligned with the sidebar as its width changes. The editor page offers icon-only Decrease/Increase Text Size actions with one-point steps from 8 to 40 points; the percentage between the controls uses the initial editor font as 100%, and font metrics keep line numbers and the active-line highlight aligned. The editor page uses standard page actions for Save and Save All; a + menu beside the Files search field offers New File and New Folder, and a GlobalDrawer provides Home, Open Folder, Developer Tools and Quit. The sidebar provides Files, Search, Git, Bookmarks, Warnings and Errors through a standard TabBar with Kirigami.NavigationTabButtons. The sidebar TabBar occupies that header in place of a heading and uses the toolbar’s single separator. Tabs use theme icons and tooltips to fit narrow sidebars. Below it, Files and Search use SearchField rows aligned with the editor document TabBar and sharing its height. Both TabBars size their buttons to the available height; document tabs include Material file icons and independent close controls. A persistent ListModel updates the native tab objects incrementally. The final active tab is selected before removing its old neighbor, avoiding a first-tab selection flash. Files and Search rows show an eye for open documents independently of their dirty marker. The document tabs’ dirty dot is anchored over the left padding, outside the title layout, so editing never changes tab width or hides the marker with a truncated name. Git, Bookmarks, Warnings and Errors display PlaceholderMessage panels explaining that their features are not available yet. Recent workspaces and search matches use SubtitleDelegate. Empty states, errors, external-change conflicts and entry creation use PlaceholderMessage, InlineMessage and Dialog/FormLayout.

The frontend follows the [Kirigami documentation](https://develop.kde.org/frameworks/kirigami/) and [KDE HIG](https://develop.kde.org/hig/). Kirigami.Theme supplies colors and typography, and Kirigami.Units supplies spacing and icon sizes. There are no forced Basic controls, rotated tabs, custom control backgrounds, fixed UI fonts or bundled action artwork. As prescribed by the [Kirigami controls guide](https://develop.kde.org/docs/getting-started/kirigami/components-controls/), buttons, text editing and tree views use Qt Quick Controls where Kirigami has no replacement. Code-specific gutter, active-line and minimap rendering remains, using theme colors instead of a fixed palette. The cursor line uses a translucent system-accent tint across the editor and gutter, following cursor movement, scrolling and appearance changes.

The app selects the KDE `org.kde.breeze` Qt Quick Controls style on every host when `QT_QUICK_CONTROLS_STYLE` is unset. Breeze does not provide TreeViewDelegate; the app selects Qt's built-in Fusion desktop fallback for missing controls unless `QT_QUICK_CONTROLS_FALLBACK_STYLE` is set. Install `qqc2-breeze-style` for the same Qt installation; an explicitly selected style takes precedence. File/folder icons use the project's bundled Material Icon Theme assets and shared Rust associations, including specialized and expanded-folder variants. Kirigami displays these assets without recoloring them. Other control/action icons use standard theme names, with Breeze Icons supplying the fallback outside KDE. KDE's configured icon theme takes precedence. Native window-manager decorations remain enabled. `KColorSchemeManager` follows the host light/dark preference through Qt style hints, applying standard Breeze/Breeze Dark colors outside KDE and retaining the configured system scheme on Plasma. Changes update Home, Workspace, controls, file rows and selection without restarting the app.

The editor uses `QFontDatabase::FixedFont`, preserving the platform's configured fixed-width font and size, with an explicit monospace hint and kerning disabled. Line numbers use the same resolved family and pixel size. The sidebar smoke test also verifies that narrow and wide ASCII characters have equal advances in the editor font.

Run cargo xtask doctor --strict kde, cargo xtask build-kde, and cargo xtask run-kde with Qt 6 development tools, Kirigami, qqc2-breeze-style, KF6 ColorScheme development headers/libraries, Breeze Icons and Qt Quick Dialogs. Kirigami and Breeze are required on macOS too; there is no environment switch or alternate generic interface. If QML loading fails, the app reports the error and exits with a failure status.

The macOS bootstrap downloads Qt Minimal 6.10.0, which does not include KDE dependencies. Use a complete matching Qt SDK to build Kirigami, qqc2-breeze-style and their KDE Framework dependencies, then install their libraries, plugins and QML modules into the Qt prefix. Alternatively, select a complete Qt/KDE SDK with QMAKE. KF6 ColorScheme headers are discovered in the Qt prefix; set `KF6_COLORSCHEME_PREFIX` when they are installed elsewhere. For separate prefixes, configure QML_IMPORT_PATH and Qt's plugin/library discovery accordingly. Extra CMake Modules and Qt's development metadata (`mkspecs` and `metatypes`) are needed to build KDE modules. The verified bootstrap uses Kirigami/Frameworks/Breeze Icons 6.22.0, ECM 6.22.0 and qqc2-breeze-style 6.6.5 with Qt 6.10.0. No Plasma session is required.

The stock Breeze 6.6.5 TextArea emits an `Unable to assign ... to QQuickTextInput` diagnostic from its mobile text toolbar on this Qt version. Desktop editing, selection, saving and pointer smoke tests pass; the frontend uses the upstream style without a local override for that toolbar.

The current-line highlight uses the native TextArea background when available. Styles without a background, including Fusion, draw it behind the text in document coordinates so it stays aligned with the gutter while scrolling.

`target/debug/native-workspace-kde --smoke` checks the default Kirigami entry point and exits. `--smoke-workspace=/path/to/disposable-fixture` checks separate Home/workspace windows, tree navigation, unsaved editor state, search, editing, and saving. The fixture needs `README.md` and `src/main.rs`; its files are modified by the test. Add `--smoke-screenshot=/absolute/path.png` to either smoke mode to capture its Home or workspace window before exiting.

`cargo xtask build kde` compiles without tests; `cargo xtask start kde` opens the existing binary; `cargo xtask run kde` combines them. `cargo xtask test kde` runs Rust tests; the GUI smoke modes below remain explicit. The hyphenated spellings remain aliases. Qt discovery and compiler overrides also apply to the new `check`, `lint` and `test` tasks. See [terminal commands](development.md#terminal-commands).

On macOS, `build-kde` and `run-kde` select the newest installed Qt 6.10+ bootstrap `qmake` from the Qt Minimal cache, ignoring unrelated entries such as Finder's `.DS_Store`. This bypasses a cache-scanning panic in qt-build-utils 0.10. Set `QMAKE` to choose another installation explicitly; `QT_MINIMAL_DOWNLOAD_ROOT` is honored for custom cache locations. When no cached installation exists, the usual Qt discovery and download remain available.

The Files tab uses Qt Quick `TreeView` and the standard `TreeViewDelegate`, including its native edit delegate. Branch indicators, selection, row height, padding and editor geometry come from Qt. The content uses the stock `Kirigami.IconTitleSubtitle` component with small Material file/folder icons, including expanded-folder variants. The fallback delegate maps its palette roles to Kirigami.Theme so the macOS system appearance cannot supply conflicting text and background colors. Native delegates keep their standard layout and background; trailing status icons show open documents, unsaved changes and external-change conflicts. Selection uses the active system palette's accent and highlighted-text roles, including when focus moves into the editor or another window. Kirigami's inherited selection roles and Qt's inactive selection palette use the same accent; Material artwork retains its original colors. A stock QIdentityProxyModel adapts TreeModel's role-name API to the numeric roles expected by Qt's default editor. Single clicks select folders and open files; expansion follows Qt's arrow/double-click behavior. Rename uses F2 or the context menu and commits with Return; clicking an already open file does not start renaming. The Search tab keeps its grouped results in a virtualized `ListView`. The sidebar groups sorted file and folder paths by parent when the workspace or search results change and caches the visible tree order. To measure the tree path on a workspace containing a populated `src` directory, run `target/debug/native-workspace-kde --benchmark-workspace=/path/to/workspace` (with `QT_QPA_PLATFORM=offscreen` for headless runs). The benchmark verifies that the native tree follows expansion, collapse, and name filtering. Its timings do not include display presentation.

Files and Search keep separate caches and models across tab changes. Workspace paths and the name filter invalidate Files; text queries and search results invalidate Search. Files, Search, recent workspaces and drag previews use the same bundled Material icons; pending moves are reported in the status bar rather than adding controls to file rows. Row bindings follow changes to the tree's visible row mapping after expansion or collapse.

Search renders parent folders and files at their path depth, with each content occurrence indented one level below its file. The sidebar smoke test checks the rendered indentation as well as cached tab switching.

The sidebar regression smoke test runs with `--smoke-sidebar=/path/to/fixture`. The fixture must contain `README.md` and `src/main.rs`, with `sidebar needle` in the Rust file. The test checks repeated tab changes without tree resets, compact native rows without clipped labels, Kirigami view palette roles, retained expansion/collapse, search and filter invalidation, and new-file updates. It exercises actual mouse clicks and native F2/Return editing while preserving unsaved buffers. It creates `src/new.rs`; use a disposable fixture. It also verifies deletion confirmation and cancellation, rejects deletion of an unsaved document, then checks file and populated-folder removal after saving. Run it with the default Breeze style; Fusion can be selected explicitly for a second style check. Its tab timings measure cached switching logic, excluding display presentation.

The native appearance smoke test runs with `--smoke-appearance=/path/to/disposable-fixture` containing `src/main.rs`. It verifies the startup appearance, switches Qt's application appearance between light and dark repeatedly, checks Home/Workspace/editor theme updates and the cursor line's translucent system accent, verifies loaded Material folder/file icons and the actual selected row's system accent and contrast with editor focus and with an inactive window in both appearances, then returns to the system preference. It changes only the test process, never the OS preference. Add `--smoke-screenshot=/absolute/prefix` to save `prefix-light.png` and `prefix-dark.png`. Run it on the native macOS platform; the offscreen platform does not support application appearance changes.

`--smoke-sidebar-layout=/path/to/disposable-fixture` exercises the actual Kirigami resize handle in the sidebar body and header. With `src/main.rs` in the fixture, it verifies widening, minimum width, header/divider alignment, equal search/document-row heights, tab buttons fitting their bars, sidebar-tab and window-size changes, retained directory expansion and unsaved editor text. Add `--smoke-screenshot=/absolute/path.png` to capture the resulting layout.

Rename cancellation uses the native tree editor or the Search field's local focus/key handlers. There is no window-sized MouseArea for outside clicks. Text and drawer resizing retain their toolkit cursors; enabled Qt/Kirigami buttons and item delegates receive a native pointing-hand cursor on hover without consuming events or overriding the application cursor. The gutter uses the text cursor, and the minimap uses open/closed-hand feedback. `--smoke-cursors=/path/to/disposable-fixture` (with `README.md` and `src/main.rs`) checks the window's resolved cursor over controls on macOS.
