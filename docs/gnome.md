# GNOME development

The GNOME frontend uses GTK4 4.8+ and libadwaita 1.9+. Run cargo xtask doctor --strict gnome, cargo xtask build-gnome, and cargo xtask run-gnome after installing the development libraries. Linux CI uses Ubuntu 26.04, which supplies libadwaita 1.9.

`cargo xtask build gnome` compiles without tests; `cargo xtask start gnome` opens the existing binary; `cargo xtask run gnome` combines them. `cargo xtask test gnome` runs Rust tests, while native GUI smoke modes remain explicit. The hyphenated spellings remain aliases. See [terminal commands](development.md#terminal-commands).

The app uses a compact, virtualized GTK ListView inside AdwOverlaySplitView. Each file row indents its icon and text together according to directory depth, and directories sort before files. Separate AdwToolbarViews let the file sidebar occupy the full window height, including its own header. The content header has a standard sidebar toggle, symbolic Save and Save All buttons with tooltips, the workspace heading, and a main menu. Both the workspace and Home windows offer Home, Developer Tools (when available), Open Folder and Quit in that menu. Menu entries and action buttons include symbolic icons. The application actions retain Control/Command-S, Control/Command-Shift-S, Control/Command-O and Control/Command-Q shortcuts. The native window title follows the open workspace name. Both header bars leave title button placement to libadwaita, so window controls follow the desktop's left or right decoration layout and move to the content header when the sidebar is hidden. The text view does not wrap long lines and enables horizontal scrolling. Document status appears below the editor. The diagnostic counter is displayed only during NATIVE_WORKSPACE_SMOKE=1.

On the macOS bootstrap host, Homebrew GTK4 4.24.1 and libadwaita 1.10.0 built and ran the app. Linux CI builds and checks diagnostic and document edit/save paths under Xvfb.

Files and Search keep separate sidebar models and scroll containers. Switching tabs reuses those views without rebuilding the file tree or rehighlighting the editor. Changes to documents, directories, search results, or the name filter invalidate the affected model so hidden views refresh when selected.

Drag the sidebar's trailing edge to resize it, including alongside the header. The handle keeps a minimum sidebar width and reserves room for the editor; the standard sidebar toggle continues to hide and show it. The workspace GUI smoke mode checks resizing, width limits and the toggle.

Inline renaming uses GTK Entry activation, Escape and a local EventControllerFocus. Moving focus out cancels the draft; no gesture on the application window captures outside clicks for rename cancellation.

Document tabs use AdwTabBar with AdwTabView. The tab bar is a top bar of the same AdwToolbarView as the header, so both share the theme background and backdrop colors. Each native page has its Material file icon, path tooltip, fixed leading dirty indicator and built-in close control. Native reordering updates the shared tab order, so closing a tab selects its visual neighbor. A transparent icon reserves the native indicator slot for clean documents, so the dirty dot stays separate from title truncation and never changes tab measurements. Page objects survive renames, and the same TextView serves the selected page. Idle snapshots do not update the tab bar, and page properties are written only when changed to preserve manual horizontal scrolling. `NATIVE_WORKSPACE_SMOKE_TAB_SCROLL=1` adds an overflow regression to the workspace smoke: twenty tabs, manual scrolling away from the selected tab, repeated idle snapshots, a dirty-marker update, touchpad gestures past both edges, immediate direction reversal and bounded inertia. Continuous surface events are captured before the native wheel handler, use logical-pixel deltas without wheel amplification, and lock to the gesture’s dominant axis after three pixels of movement. The native strip and tab actions stay intact; touchpad scrolling stops at the edges without GTK overshoot, with bounded libadwaita inertia on release. Discrete wheel events retain their native handling. `NATIVE_WORKSPACE_SMOKE_SCREENSHOT=/absolute/path.png` captures the final workspace.

The header provides linked Decrease/Increase Text Size buttons, using one-point steps from 8 to 40 points. A percentage between the controls uses the initial editor font as 100%. The editor font and line-number gutter resize without modifying the document or its undo history.

File rows show an eye for documents open in the editor, in addition to their dirty/conflict status. Open/close snapshots update the visible row indicators without rebuilding the cached tree or name-filter index.
